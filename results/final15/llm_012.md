## The defect I found

With `tileRows = tileColumns = 1`, every PE is its own tile, so the machine's critical path is exactly one PE: `reg → multiply+add → reg`. v3 put the 8-bit zero-comparator **in series at the front of that path**, feeding the select of the mux that feeds the multiplier. But that mux is a **tautology**: muxing a constant zero in *because the operand already is zero* is a no-op. All three cases of `(a, valid)` give the same result as `Mux(valid, a, 0)`. v3 was paying ~3–4 gate levels of comparator, ahead of a ~20-level path, to choose between two values that are equal whenever the comparator fires.

I kept `sc_gate` and both structures that make T-A a genuine accumulator bypass — the `in_c` zero-isolation and the `out_b` bypass — because those selects resolve *in parallel* with the multiplier, not in series with it, so the comparator is hidden behind them.
